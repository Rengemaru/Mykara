# Proposals for Improvement
**歌帳 ブラッシュアップ提案書**
作成日: 2026-06-19

---

## 1. 調査概要

本レポートは5つの調査軸を並列で分析し、歌帳の設計思想を壊さない機能改善案をまとめたものです。

| 調査軸 | 内容 |
|---|---|
| コードベース分析 | 現在の実装状態・設計制約・拡張性の評価 |
| 国内カラオケアプリ調査 | DAMとも・JOYSOUND公式アプリ・サードパーティ点数管理アプリとの比較 |
| 類似カテゴリUX調査 | 筋トレログ・ゴルフスコア・語学学習アプリのUXパターン |
| カラオケユーザーのニーズ分析 | ユーザーが抱えるリアルな課題の抽出 |
| 技術トレンド・差別化機能分析 | React Native / Expo で実現できる革新的機能の評価 |

---

## 2. アプリの設計思想（現状確認）

調査の結果、歌帳のコアバリューは以下の3点に集約されます。
これらはすべての提案における「壊してはいけない軸」です。

| コアバリュー | 内容 |
|---|---|
| **機種横断の一元管理** | DAM・JOYSOUND両機種のスコアを1アプリで比較できる（公式アプリは自社機種のみ） |
| **オフライン完結の高速入力** | 店舗でWi-Fiなし・テンキー数タップで記録完結 |
| **自由カテゴリ＋キー記録** | タブによる自由分類とキーオフセット管理（類似アプリにほぼない観点） |

## 3. 市場調査結果

### 3-1. 国内カラオケアプリとの比較

| アプリ | 強み | 弱み（歌帳が勝る点） |
|---|---|---|
| **DAMとも** | 機器連携・精密採点履歴閲覧・音程正解率可視化 | DAM専用・タブ管理なし・オフライン不可 |
| **JOYSOUND公式** | 歌唱履歴確認・SNS共有 | JOYSOUND専用・手入力不可・店舗会員カード前提 |
| **サードパーティ点数管理** | シンプルな記録 | 曲名/日付/点数の3点のみ・カテゴリ管理なし・グラフなし |

**歌帳が公式アプリに対して持つ差別化領域：**
- DAM/JOYSOUND横断の一元管理
- キー（音域）オフセットの記録
- タブによる自由カテゴリ分け
- バックアップ・リストア（機種変更対応）

### 3-2. カラオケユーザーのリアルな課題（トップ8）

1. **選曲迷子** — 大量の持ち歌から「今日何を歌うか」を素早く決められない
2. **上達の見えにくさ** — 点数が上がっているのか感覚でしか分からない
3. **伸び悩み曲の放置** — どの曲を重点練習すべきか判断できず惰性で同じ曲を歌い続ける
4. **機種スコアの混乱** — DAMで90点・JOYSOUNDで75点など機種差を忘れて過信・過小評価する
5. **十八番を即答できなさ** — 「十八番は？」と聞かれたときスコア根拠を持って答えられない
6. **長期未歌唱曲の劣化見落とし** — 半年ぶりに歌うと歌詞・音程が崩れているのに記録がない
7. **グループカラオケの曲かぶり** — 友人と行ったとき誰が何を歌うか事前に整理できていない
8. **モチベーションの波** — 点数が伸びない時期に「どこまで練習すればいいか」の目標が見えない

### 3-3. 類似カテゴリアプリの優れたUXパターン（歌帳適用評価付き）

| UXパターン | 由来アプリ | 歌帳への適合性 |
|---|---|---|
| 自己ベスト更新アニメ | Strong / Strava | ◎ スコア保存時に `best_score` と比較するだけで実現可 |
| グラフの最高値・最新値マーカー | Garmin Connect | ◎ gifted-charts の設定変更のみ |
| カテゴリ別件数バッジ | Strong / BandHelper | ◎ クエリ1本追加で実現 |
| セッション単位の振り返り | ゴルフスコアアプリ | ◎ `session_date` が既存のため自然に拡張可 |
| 課題・成長コメント生成 | Hevy | ○ ローカル集計のみ・API不要 |
| 目標スコア設定＋グラフライン | Duolingo / ゴルフ | ○ songs テーブル拡張で実現可 |
| ストリーク（連続記録） | Duolingo | △ カラオケ頻度が不定のため離脱リスクあり |
| ヒートマップカレンダー | GitHub / Habitica | △ 実装コスト高・優先度低 |
| SNSシェア用スコアカード | Strava / Wordle | △ 任意オプションならあり・強制は設計思想と競合 |

## 4. 機能改善提案

### Phase A — 低コスト・即効性あり（1〜2日で実装可能）

#### A-1. タブに曲数バッジを表示

```
すべて (35)  │  十八番 (8)  │  練習中 (12)  │  アニソン (5)
```

- **解決する課題**: 選曲迷子（課題 #1）
- **実装方法**: `useTabs` フックで JOIN count を追加するだけ。DB変更不要
- **実装難易度**: 低

---

#### A-2. 自己ベスト更新バナー（PBバナー）

スコア保存時、`best_score` を超えたら「🎉 自己ベスト更新！」をアニメーション表示する。

- **解決する課題**: 上達の見えにくさ・モチベーションの波（課題 #2・#8）
- **実装方法**: DB に `best_score` は既存のため比較コストゼロ。アニメは React Native の Animated API で実装
- **実装難易度**: 低

---

#### A-3. グラフの最高点・最新点マーカー強調

gifted-charts の `dataPointsColor` / `dataPointsRadius` 設定を変更し、最高点に★、最新点に●を付ける。

- **解決する課題**: グラフが見にくく自己ベストがどこか分からない（課題 #2）
- **実装難易度**: 低

---

#### A-4. セッション終了サマリー画面

「今日の記録：3曲・自己ベスト更新2曲・最高スコア 92.450（◯◯）」を当日の帰り際に表示する。

- **解決する課題**: 今日どれだけ頑張ったか振り返れない（課題 #8）
- **実装方法**: `session_date` で当日スコアを集計するだけ。既存設計の自然な拡張
- **実装難易度**: 低

---

### Phase B — 中コスト・差別化効果大（1〜2週間）

#### B-1. 曲の並び替えオプション拡張

ホーム画面の曲一覧に以下のソート軸を追加する。

| 並び順 | 解決する課題 |
|---|---|
| 最高スコア順 | 十八番を根拠を持って即答できない（課題 #5） |
| 記録回数順 | よく歌う曲・歌わない曲の把握 |
| 最終記録日順（古い順） | 長期未歌唱曲の発見（課題 #6） |
| スコア伸び率順 | 重点練習すべき曲の発見（課題 #3） |

- **実装方法**: `getAllSongs` のクエリにソート条件を追加。UIはホーム画面のフィルターバー拡張
- **実装難易度**: 低〜中

---

#### B-2. 長期未歌唱フィルター

「3ヶ月以上記録がない曲」だけ表示するフィルターをホームに追加する。

- **解決する課題**: 半年ぶりに歌うと崩れているのに気づかない（課題 #6）
- **実装方法**: `MAX(scored_at)` から日数計算するだけ。DB追加不要
- **実装難易度**: 中

---

#### B-3. 曲ごとのスコア目標設定

曲ごとに「目標スコア（例: 90点）」を設定し、グラフに目標ラインを引く。達成時にPBバナー（A-2）と連動して祝福メッセージを表示する。

- **解決する課題**: モチベーションの波・どこまで練習すればいいか見えない（課題 #8）
- **実装方法**: `songs` テーブルに `goal_score REAL` カラムを追加（マイグレーション v4）
- **実装難易度**: 中

---

#### B-4. 今日のセットリスト（一時リスト機能）

カラオケ当日に「今日歌う予定の曲」を一時的にリストアップできる機能。翌日または退店操作で自動クリア。

- **解決する課題**: 選曲迷子・グループカラオケの曲かぶり（課題 #1・#7）
- **実装方法**: `session_date` の概念を活かし、既存タブとは分離した一時リストとして実装
- **実装難易度**: 中

---

#### B-5. 月次統計サマリー

ホームまたは設定画面の上部に「今月○回記録・最もスコアが伸びた曲・記録更新数」を表示する。

- **解決する課題**: 上達の見えにくさ・振り返りの欠如（課題 #2）
- **実装難易度**: 中

---

### Phase C — 将来フェーズ・高い差別化価値

#### C-1. キー × スコア相関チャート

`key_offset` 別の平均スコアを棒グラフで表示する。「キー-2が一番点が出る」といった発見を促す。他のカラオケアプリには存在しない歌帳固有の分析機能。

- **実装方法**: `key_offset × score` を SQL で集計、gifted-charts の棒グラフで表示
- **実装難易度**: 中

---

#### C-2. 機種別得意度サマリー

DAM平均スコア vs JOYSOUND平均スコアを比較し「あなたはDAM向き」と示す。機種差の混乱を整理する。

- **解決する課題**: 機種スコアの混乱（課題 #4）
- **実装難易度**: 中

---

#### C-3. CSVエクスポート

既存のJSON バックアップに加え、スプレッドシート等へのエクスポートに対応する。
（CLAUDE.md Phase 6 候補として明記済み）

- **実装難易度**: 低〜中

## 5. 「やらない」ことの整理

設計思想を守るために、以下は意図的に採用しない。

| 機能 | 不採用の理由 |
|---|---|
| SNS自動共有・ソーシャル機能 | ローカルファーストの思想と競合。任意オプションとしてならあり |
| クラウド同期 | JSONバックアップで代替可能。実装コスト・複雑度に見合わない |
| ストリーク（連続記録の強制） | カラオケ頻度は不定のため、途切れるとむしろ離脱を招く |
| アプリ内広告 | 入力操作中の広告はUXを致命的に破壊する |
| 楽曲の音声再生 | 著作権・ライセンスコストが発生する。アプリのスコープ外 |

## 6. 実装優先度マトリクス

```
効果
 高 │ A-2 PBバナー    B-1 並び替え拡張
    │ A-4 セッションサマリ  B-3 スコア目標
    │                B-4 セットリスト
    │ A-1 タブバッジ
    │ A-3 グラフ強調  B-2 未歌唱フィルター
 低 │               C-1 キー相関  C-2 機種得意度
    └──────────────────────────────────────
         低               高          実装コスト
```

**推奨スタート**: A-1（タブバッジ）→ A-2（PBバナー）→ A-4（セッションサマリー）の3点セット。
ほぼコストゼロで「使い続けたくなる体験」が大幅に向上します。
その後 B-1（並び替え拡張）で「選曲迷子」を解消するのが王道ルートです。
